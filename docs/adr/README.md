# Architecture Decision Records

Registre aqui decisoes que alterem limites arquiteturais, contratos, modelo de dados ou operacao.

Cada ADR deve conter:

1. contexto e problema;
2. decisao adotada;
3. alternativas relevantes;
4. consequencias positivas e negativas;
5. status e data.

Use nomes sequenciais no formato `NNNN-titulo-curto.md`. ADRs aceitos nao sao reescritos para ocultar
decisoes anteriores; uma nova decisao deve substituir explicitamente a anterior.
